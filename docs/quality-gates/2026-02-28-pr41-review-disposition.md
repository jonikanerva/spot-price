## Reviewed Findings and Disposition

### F1: Plaintext API key auth lookup

- Finding: auth resolves API keys by `key_plaintext` in `api_keys`.
- Decision: **Accepted by owner**.
- Rationale: product intentionally optimizes copy-first UX (key and Home Assistant examples visible on every login). API keys are low-value credentials for personalized price settings and can be regenerated by users.

### F2: Migration could silently drop null-plaintext legacy rows

- Finding: `007_drop_api_key_hash_and_name.sql` originally filtered on non-null plaintext and could silently remove hash-only rows.
- Decision: **Mitigated in code**.
- Mitigation: migration now fails fast if any `api_keys.key_plaintext IS NULL` rows exist, preventing silent key invalidation.

### F3: Registration cap changed to 100,000

- Finding: `MAX_USERS` changed from 100 to 100000.
- Decision: **Accepted by owner**.
- Rationale: explicit owner request to raise cap for current growth goals.
